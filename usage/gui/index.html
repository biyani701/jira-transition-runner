    GUI — Desktop Interface¶

    A tkinter-based GUI ships alongside the CLI and mirrors the full feature set — no terminal required.

    Launch¶

    # Via installed script
jira-runner-gui

# Or directly
python -m jira_transition_runner.gui

    Layout¶

    The window has three sections:

    1. Global settings (top panel) — project key and workflow YAML path, shared by all tabs.
    2. Tab panel — one tab per operation mode.
    3. Output console (bottom) — live stdout/stderr stream with colour-coded tags.

    Global Settings¶

    Field Description
    Project key Jira project key (e.g. PROJ)
    Workflow YAML Path to transition.yaml; use Browse… to pick a file

    Phase 1 — Plan Tab¶

    Field Description
    JQL query Multi-line text area for your JQL
    Output Excel Destination file; defaults to plan.xlsx
    Include child issues Enables hierarchical lookup
    Generate Plan Runs Phase 1 in a background thread

    Phase 2 — Execute Tab¶

    Field Description
    Plan Excel file Plan file from Phase 1; use Browse…
    Dry run Simulates transitions without applying them
    Execute Plan Runs Phase 2 in a background thread

    Version Management Tab¶

    Field Description
    Action Release or Archive
    Versions source Manual (comma-separated) or From Excel file
    Version names / Excel file Input for version names
    Release date Defaults to today; edit for a custom date
    Dry run Simulates without applying changes
    Manage Versions Runs version management in a background thread

    Output Console¶

    • Output is streamed in real time from the background thread.
    • ANSI escape sequences are stripped automatically.
    • Colour coding: normal output (grey), success (teal), warnings (yellow), errors (red).
    • Clear wipes the console; Copy all copies the full text to the clipboard.

    Notes¶

    • All operations run in a daemon thread — the UI stays responsive.
    • Only one operation can run at a time; all buttons are disabled while busy.
    • Settings (settings.toml and the JIRA_ENV environment) are loaded at startup the same way as the CLI. The active environment and Jira URL are shown under Global settings.
